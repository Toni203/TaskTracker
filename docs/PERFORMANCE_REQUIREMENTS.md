\# Требования к производительности будущей веб-версии TaskTracker



\## 1. Загрузка данных



\- Приложение не должно загружать большой объём данных, который пользователь в данный момент не использует.

\- Основная информация (название, краткое описание) отображается сразу.

\- Тяжёлые данные (комментарии, вложения, история) загружаются только по запросу пользователя.



\## 2. Большие списки



\- Для большого количества задач необходимо использовать постраничную (pagination) или постепенную (lazy loading) загрузку данных.

\- Не допускается загрузка и отображение 20 000 задач одновременно.

\- Рекомендуемый размер страницы: 50–100 задач.

\- Обязательны фильтрация и поиск на стороне сервера.



\## 3. Клиентский JavaScript



\- Тяжёлые вычисления на клиенте должны выполняться только при необходимости.

\- Длительные операции не должны блокировать интерфейс.

\- Для тяжёлых операций использовать Web Workers.

\- Учитывать различия в скорости работы JavaScript в разных браузерах.



\## 4. Медиа и вложения



\- Изображения и вложения не загружаются автоматически вместе с карточкой задачи.

\- Загрузка медиа происходит только после действия пользователя.

\- Для больших изображений использовать предпросмотр (thumbnail).



\## 5. Работа на слабых компьютерах



\- Приложение должно оставаться работоспособным на компьютерах с небольшим объёмом RAM.

\- Не допускается одновременная загрузка большого количества вкладок с тяжёлым содержимым.

\- Интерфейс должен корректно работать в браузерах Firefox и Microsoft Edge.



\## 6. Проверка производительности



\- Измерения проводятся в Firefox и Microsoft Edge.

\- Проверяется RAM и загрузка CPU при разном количестве вкладок.

\- Выполняется JavaScript-тест для оценки скорости выполнения.

\- Результаты сравниваются между браузерами и версиями.

\- На основе измерений определяются узкие места и требования.
